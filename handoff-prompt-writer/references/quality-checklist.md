# 交接提示词质量门禁清单（Quality Checklist）

交付前逐项检查。**阻断项**任何一条不通过，都不能交付；**建议项**不通过时，在确认不影响接手的前提下可以交付。

## A. 冷启动测试（阻断项）

以零上下文接手者的身份，只读交接提示词，回答：

- [ ] 最终目标是什么？做到什么程度算完成？
- [ ] 现在处于什么状态？哪些是已验证的？
- [ ] 第一步具体做什么（文件/函数/命令）？
- [ ] 哪些事不能做？哪些方案已证伪、不要重试？
- [ ] 遇到模糊情况时，按什么原则取舍？
- [ ] 怎么确认自己没有破坏已完成的部分？

## B. 事实与证据（阻断项）

- [ ] 状态快照来自本次实际采集（脚本或 git 命令），不是凭记忆
- [ ] 标为 `[已验证]` 的项目都有测试、命令输出或 commit 作为证据
- [ ] 写了但没运行过的代码标为 `[未验证]`，而不是“已完成”
- [ ] 推断内容标注了 `[假设]`
- [ ] 如果存在上一份交接文档，其中的状态声明已重新核实

## C. 可解析性（阻断项）

- [ ] 没有“那个”“上面的”“刚才的”“之前讨论的”这类悬空指代
- [ ] 提到的每个文件都有路径，关键位置有行号
- [ ] 提到的报错有原文关键行
- [ ] 提到的决策有编号和内容，而不是“按之前的方案”

## D. 安全（阻断项）

- [ ] 不含 token、密码、私钥、连接串、Cookie 值
- [ ] 环境变量只写名称，不写值
- [ ] 用户粘贴的外部内容中如有敏感信息，已脱敏

## E. 用户意图保真（阻断项）

- [ ] 用户的关键要求和中途纠正已保留，并尽量引用原话
- [ ] 未决问题没有被写成已决定
- [ ] 与 `AGENTS.md` / `CLAUDE.md` 没有冲突的指令

## F. 信息取舍（建议项）

- [ ] 包含“已排除路径”（如果本会话有过失败尝试）
- [ ] 决策写明了理由与推翻条件
- [ ] 没有粘贴可以用指针替代的大段代码或日志
- [ ] 没有解释通用知识
- [ ] 篇幅在所选档位的预算内；超出时已按 D → C → B 顺序裁剪

## G. 可执行性（建议项）

- [ ] 接手协议列出了 1–3 个必读文件，并说明了原因
- [ ] 核对命令写明了预期结果
- [ ] 下一步 #1 可以立即执行，不需要先提问
- [ ] 下一步各项都有验证方式
- [ ] 写明了新会话是“核对后自主继续”还是“先复述确认”

## H. 大型项目附加（完整版适用）

- [ ] 已处理未提交/未推送的改动（已提交 WIP，或逐个列出文件及完成度）
- [ ] 任务看板按模块或阶段列出状态
- [ ] 已冻结的接口契约写明了位置和依赖方
- [ ] 测试基线写明了哪些失败是原本就有的
- [ ] 环境与命令齐全（安装、构建、运行、测试、环境变量名称）
- [ ] 协作状态齐全（分支、PR、CI、未处理的评审意见）
- [ ] 交接历史每次一行，已完成的稳定工作压缩为摘要

## I. 交付形式（建议项）

- [ ] 内联提示词放在一个代码块中；内部含代码块时外层用四个反引号
- [ ] 代码块外的说明不超过 3 行
- [ ] 已提醒用户处理未提交改动（如有）和建议迁移到项目规则文件的条目（如有）
- [ ] 交付后没有继续做开发任务
